## 5. 开发与测试中发现并修复的真实缺陷

这些不是"编出来的问题"，都是实际跑起来才暴露的：

### 5.1 FAT 的 254 与"最后一个数据块"撞号（严重）

- **现象**：把磁盘写满时，`IndexOutOfBoundsException: Index 205 out of bounds for length 205`。
- **原因**：FAT 表项只有 1 字节，`RESERVED = 254` 同时又是最后一个数据块的块号（254）。
  `chainOf` 里"下一块 == 254 就当作保留块、提前收尾"，导致跨到第 254 块的链被截断 1 块。
- **修复**：链遍历只看"是否落在 5~254 数据区"，保留块改用 `Fat.isReservedBlock(blockNo)`
  按块号判断；`freeChain`、`kindOf`、磁盘网格着色同步修正。
- **回归测试**：`FileSystemTest.chainCrossingBlock254IsNotTruncated`。

### 5.2 根目录在第 2 块，不在数据区

- **现象**：第一次启动就报"根目录最多 8 个目录项，已满"。
- **原因**：`Fat.chainOf(2)` 只接受 5~254 的块，根目录块 2 返回空链，
  遍历时被当成"已满"。
- **修复**：`FileSystem.directoryChain(int)` 对根目录特判返回 `[2]`。

### 5.3 格式化后保留块标记没有持久化

- **现象**：格式化并重开镜像后，空闲块数比实际多 5 块（块 0、1、3、4、255 被当成空闲）。
- **原因**：`Fat.reset()` 只清空数据区，没有把保留块写成 `RESERVED`。
- **修复**：`RESERVED_BLOCKS = {0,1,2,3,4,255}`，`reset()` 统一写入。

### 5.4 默认文件名超过 3 字符

- **现象**：安装默认文件树时抛"文件名过长，最多 3 个字符"。
- **原因**：最初用了 `HELP.T`、`READ.T`。
- **修复**：改成 `HLP.T`、`RED.T`（这也是为什么界面上的帮助文件叫 HLP.T）。

### 5.5 扩展名显示成小写

- **现象**：目录列表显示 `P01.e`、`HLP.t`，和命令行里输入的 `P01.E` 看起来不一致。
- **原因**：存储时扩展名统一小写（省一次比较），`getFullName()` 直接拼了小写。
- **修复**：存储仍小写，`getFullName()` 显示时转大写。

### 5.6 中文在 Swing 里显示成方块

- **现象**：进程名、日志全是"豆腐块"。
- **原因**：等宽字体 Consolas 没有中文字形。
- **修复**：`Theme` 增加 `CONSOLE_FONT_NAME`（优先 Sarasa Mono SC / 新宋体 / 微软雅黑），
  用 `canDisplayUpTo("进程管理")` 实际检测字形；数字/十六进制仍用等宽字体。

### 5.7 Git Bash 下 Maven 无法启动

- **现象**：`mvn` 报 `ClassNotFoundException: Launcher`。
- **原因**：Maven 的 shell 脚本在 MINGW 分支把 `/d/...` 形式的 Unix 路径传给 Windows 版 java。
- **修复**：提供 `scripts/mvn.sh`，直接用 `java + plexus-classworlds` 启动并传 Windows 路径。

## 6. 测试设计说明

### 为什么这些测试"不是摆设"

1. **断言精确到寄存器**：`时间片 3 时两个进程交替推进` 断言的是 `PC=4、X=4`。
   只要 `saveTo/restoreFrom` 有一处漏了，数字就对不上。
2. **断言精确到块号**：`FAT 前 128 项在 0、1 块，后 128 项在 3、4 块` 直接验证两段式布局。
3. **断言收支平衡**：文件删除后 `freeBlocks()` 必须精确恢复到操作前的值，
   任何一处块泄漏都会让这个等式失败。
4. **断言状态一致性**：综合场景六要求
   `all == running + ready + blocked + pending` 且 `free + used == 250`，
   相当于一个轻量的"不变量检查"。
5. **覆盖失败路径**：重名、空间不足、只读、表满、非法指令、目录满、非空目录删除……
   每个错误分支都有对应用例，而不是只测 happy path。

### 可复现性

所有涉及随机的用例都固定种子（`new OperatingSystem(dir, 20261027L, false)`），
且默认关闭随机到达。因此测试可以反复运行、结果完全一致；
`ProcessSchedulingTest.randomArrivalCreatesProcesses` 单独验证"打开随机到达后确实会有进程"。

### 测试数据用临时目录

每个用例用 JUnit 的 `@TempDir`，测试结束后自动清理，
不会污染项目目录，也不会因为上一轮的 `disk.img` 影响下一轮。

## 7. 未自动化的部分（如实说明）

| 部分 | 为什么 | 怎么验证的 |
|---|---|---|
| Swing 界面渲染 | 断言像素没有意义，且需要显示环境 | 手工运行 + 截图检查 8 个区域、中文显示、分割条位置、磁盘网格 32×8 |
| 界面与模型的交互（右键菜单、按钮） | 需要 UI 测试框架（如 AssertJ Swing），课程未要求 | 手工点测：启动/暂停、单步、重置、右键撤销进程、右键编辑文件 |
| 极端并发（同时点多个按钮） | 所有模型调用都在 EDT 上串行，不存在并发 | 代码结构保证（见 ARCHITECTURE 第 5 节） |
| 磁盘镜像被外部破坏 | 属于容错范畴 | `chainOf` / `readChain` 有坏链保护，最多提前结束，不会死循环 |

界面手工验证的检查清单：

1. 8 个区域全部可见，中文无方块；
2. 启动后自动出现进程，进程表的 PC/X/时间片随 tick 变化；
3. 内存条随进程创建/结束伸缩，分区颜色区分已装入/仅占用；
4. 设备卡片显示"占用中/剩余 3"，等待队列显示 `P3(5)`；
5. 磁盘网格 256 格，FAT/根目录/已用/空闲/保留 5 种颜色，点击显示块的 FAT 值与归属；
6. 命令区输入 `dir`、`run \BIN\P01.E`、`fdisk` 输出正常且有颜色；
7. 日志区随运行增长，按级别着色；
8. 关闭窗口后 `disk.img` 仍在，重新打开文件树完整。

## 8. 如何重跑并查看结果

```bash
# 全部测试
./scripts/mvn.sh test

# 只跑某个类
./scripts/mvn.sh test -Dtest=FileSystemTest

# 只跑某个方法
./scripts/mvn.sh test -Dtest=FileSystemTest#chainCrossingBlock254IsNotTruncated

# 看详细报告
cat target/surefire-reports/cn.scau.os.fs.FileSystemTest.txt
```

如果测试失败，报告里会带断言消息（中文），例如：

```
expected: <1> but was: <0> ==> 第三个进程应在排队
```

消息本身就是"期望的行为"，比只看行号好定位。
