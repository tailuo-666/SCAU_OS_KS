# 学习指南：从"看得懂"到"改得动"

这份指南面向三类人：

- **要交课程设计的同学**：按第 1、2 节走，一周内能讲清全部设计；
- **想真正理解操作系统课件的同学**：按第 3 节的 8 个实验动手改；
- **答辩前突击的人**：直接看第 5 节的"必须能回答的 10 个问题"。

---

## 1. 三天速通路线

### 第 1 天：跑起来 + 看现象

| 时间 | 做什么 | 产出 |
|---|---|---|
| 30 min | 按 README 编译、跑测试、启动界面 | 看到 88 个测试全绿 |
| 30 min | 在命令区依次输入 `dir`、`fdisk`、`type \BIN\P03.E`、`run \BIN\P04.E`、`ps` | 理解"文件 → 进程"的关系 |
| 60 min | 打开自动运行，观察 5 分钟：进程表、内存条、设备卡片、磁盘网格、日志 | 能说出"一次 tick 里界面变了什么" |
| 30 min | 暂停，用"单步"一步一步走，每步看 PC/X/时间片 | 理解时间片与中断 |

**要能回答**：为什么 P03 跑到第 6 条指令会"换人"？为什么设备卡片上的剩余时长会减少？

### 第 2 天：读代码主线

按 `CLASS_GUIDE.md` 第 1 节的 6 个文件顺序读，每个文件只抓三件事：

| 文件 | 抓什么 |
|---|---|
| `Disk` | 块大小、总块数、按块读写 |
| `Fat` | 两段式布局、`allocateChain`、`chainOf` |
| `FileSystem` | `lookup` 怎么走路径、`createFile` 怎么分配块 |
| `OperatingSystem` | `tickInternal` 的 7 步 |
| `ProcessManager` | 5 个原语与 4 个队列 |
| `MainFrame` | `refresh()` 怎么把快照发给 8 个面板 |

**要能回答**：`run` 一条命令，从键盘到进程进入就绪队列，经过了哪 8 个方法？

### 第 3 天：对着测试读行为

打开 `ProcessSchedulingTest`，把每个用例名当成"行为规格"，回到代码里找对应实现。
然后自己写 2 个新用例（见第 3 节实验 1、2），跑通。

**要能回答**：如果我把时间片改成 2，P03 会在哪些 tick 切换？

## 2. 一份"讲解用"的 15 分钟脚本

答辩或汇报时按这个顺序讲，逻辑最顺：

1. **一句话**：这是一个用 16 KB 文件当磁盘、能真的跑进程的模拟操作系统。
2. **打开界面**（30 秒）：指 8 个区域，说明"全部来自同一份快照"。
3. **文件系统**（3 分钟）：`fdisk` 讲磁盘布局 → 讲课程规格矛盾与两段式 FAT →
   `dir \BIN` 看目录项（起始块、长度、块数）→ 点磁盘网格看某文件占的块。
4. **进程**（4 分钟）：`run \BIN\P03.E` → 单步走 6 步 → 第 6 步时间片中断 →
   讲 PCB 里的 PC/X 怎么保存恢复。
5. **设备**（3 分钟）：同时 run 三个 `\BIN\P04.E` → 看设备卡片与阻塞状态 →
   讲倒计时归零 → 唤醒 → 设备直接交给队首。
6. **内存**（2 分钟）：run 多个进程看内存条伸缩 → 撤销一个 → 看分区合并。
7. **工程性**（2 分钟）：88 个测试、命令层不依赖 Swing、界面只读快照、
   发现并修复的 254 号块 bug。

## 3. 8 个动手实验（由易到难）

每个实验都给了"改哪里 / 怎么验证 / 会踩什么坑"。

### 实验 1：改时间片，观察切换次数

- **改**：`OperatingSystem.DEFAULT_QUANTUM` 改成 2（或界面上拖动时间片滑块）。
- **验证**：`run \BIN\P03.E`（8 条指令），数日志里"时间片中断"出现几次。
  时间片 6 → 1 次；时间片 2 → 3 次（第 2、4、6 条后），最后一次是 `end`。
- **坑**：时间片改成 1 时，每条指令后都切换，此时若有多个进程，
  每个 tick 都在"保存现场→恢复现场"，能看到 PC 一直是 1、2、3……

### 实验 2：写一个新测试，验证 X 的上界饱和

- **做**：新建用例：`x=99`、`x++`、`x++`、`end`，断言最终 `X == 255`（不是 101）。
- **改哪里**：不用改代码，`Cpu.executeStep` 的 INCREMENT 分支已经做了饱和。
- **验证**：`./scripts/mvn.sh test -Dtest=你的测试类`。
- **进阶**：把饱和改成回绕（`x = (x + 1) & 0xFF`），看哪些测试会失败。

### 实验 3：加一条新指令 `x+=n`

- **改**：
  1. `InstructionCodec` 里找一个空闲机器码（比如 133），增加 `CODE_ADD`；
  2. `assembleLine` 解析 `x+=5`；
  3. `decode` 增加分支；
  4. `Cpu.executeStep` 增加 `case ADD`：`x = Math.min(255, x + value); pc++`；
  5. `InstructionCodecTest` 加编码/解码/汇编用例。
- **验证**：写一个 `x=1`、`x+=5`、`end` 的程序，跑完 X 应为 6。
- **坑**：别用 103~132 之间的码（设备指令占用）；`decode` 里记得先 `& 0xFF`。

### 实验 4：把用户区从 512 字节改成 1 KB

- **改**：`MemoryManager.USER_MEMORY_SIZE = 1024`，
  同时检查 `MemoryPanel` 的坐标换算（它按比例画，一般不用改）。
- **验证**：现有测试里所有硬编码 512 的断言要一起改（`MemoryManagerTest`、`ProcessSchedulingTest`）。
- **坑**：`largestFreeBlock`、`freeBytes` 的断言都写了 512，改完记得全局搜。

### 实验 5：加第四类设备 D（4 台）

- **改**：
  1. `DeviceType` 加 `D("D", 4)`；
  2. `InstructionCodec.CATEGORY` 增加 D 的类别号 3（机器码 133~142，正好接在 C 后面）；
  3. `encodeDevice`/`decode` 自动支持（按类别算），但要确认 `CODE_DEVICE_MAX` 从 132 改成 142；
  4. `DeviceManager` 不需改（按 `DeviceType.values()` 建表）；
  5. 界面设备区会自动多出 4 张卡片（如果按 values() 遍历）。
- **验证**：写 `!D3` 的程序，跑起来能看到 D1 被占用。
- **坑**：`DeviceType.fromChar` 要加 case；`Cpu` 里 `DeviceType.fromChar(decoded.getDevice())` 会自动走通。

### 实验 6：实现"目录也排序插入"

- **现状**：`list()` 输出时排序，磁盘上的目录项按创建顺序排列。
- **改**：`FileSystem.addEntry` 找到空槽后，把该项插入到"名称序"正确的位置（需要移动后续项）。
- **验证**：`dir \BIN` 的顺序应与文件名严格升序，且删除中间项后仍然有序。
- **坑**：跨块时要在两个块之间移动项，别忘了目录链可能不止 2 块。

### 实验 7：加"优先级调度"

- **改**：
  1. `Pcb` 加 `priority` 字段；
  2. `ProcessManager.dispatch()` 从"取队首"改成"取优先级最高（相同则先来先服务）"；
     `readyQueue` 可以继续用 `LinkedList`，只是改为遍历找最大；
  3. `SystemSnapshot.PcbView` 加字段，`ProcessPanel` 加一列；
  4. 命令 `run /p5 \BIN\P01.E` 支持指定优先级。
- **验证**：创建 3 个不同优先级的进程，观察执行顺序；再让高优先级进程被设备阻塞，
  低优先级应能获得 CPU（这就是"优先级 + 阻塞让出"）。
- **坑**：时间片用完放回队列时不能改优先级；低优先级长期得不到 CPU 的"饥饿"问题
  可以用"老化"（等待越久优先级越高）解决。

### 实验 8：实现"二级索引"文件（大文件）

- **现状**：FAT 链式分配，最大文件受长度字段（2 字节）限制 65535 字节。
- **改**（工作量较大）：
  1. 目录项增加"索引块"字段（需要改 8 字节布局或另开一块存扩展信息）；
  2. 索引块里放 64 个块号（每项 1 字节）；
  3. `readFile/writeFile` 增加"索引模式"分支；
  4. 对比链式与索引式的随机访问代价（找第 n 块：链式 O(n)，索引 O(1)）。
- **验证**：写一个 8 KB 文件，随机读第 100 块附近的内容，比较两种方式的块读取次数。
- **坑**：这会让目录项超过 8 字节，需要考虑兼容性——正好可以练习"格式升级"。

## 4. 调试技巧

### 4.1 用日志代替断点

日志每条都带 `[时间] 级别 消息`，例如：

```
[6] 进程 时间片中断：P1 用完 6 个时间单位，保存现场 PC=6 X=6，重新调度
[3] 设备 P2 申请 A 类设备成功，使用 3 个时间单位，进程转入阻塞
```

想看某个时刻发生了什么，直接把日志按时间过滤。

### 4.2 用测试复现，而不是靠手点

```java
OperatingSystem os = new OperatingSystem(tempDir, 1L, false);
Pcb p = os.startProcess("\\BIN\\P04.E");
os.runTicks(2);
assertEquals(ProcessState.BLOCKED, p.getState());   // 精确定位到第 2 个 tick
```

比"点开始、看界面、猜哪里不对"快得多。

### 4.3 常见"看起来是 bug 其实不是"

| 现象 | 其实是 |
|---|---|
| 文件名超过 3 字符报错 | 8 字节目录项的规格限制 |
| 根目录建第 9 个东西失败 | 根目录固定 1 块、8 项 |
| 三个进程抢 2 台设备却没排队 | 设备在第 5 个时间单位就释放了，第三个进程还没申请（用 `!A9` 才能看到排队） |
| `end` 之后 PC 没加 1 | `end` 不推进 PC，PC 仍指向 `end` |
| 进程一直不结束 | 时间片设得很大 + 程序里申请了长设备 |

## 6. 继续深入的方向

| 方向 | 可以做什么 |
|---|---|
| 调度算法 | 优先级、多级反馈队列（MLFQ）、最短作业优先，与轮转对比平均周转时间 |
| 内存管理 | 最佳适配/最差适配、分页（把 512 字节切成固定页）、页面置换（LRU/Clock） |

| 并发 | 信号量/PV 操作模拟生产者消费者（在单 CPU 逻辑时钟下做"原语不可打断"） |
| 死锁 | 设备申请顺序造成环路，实现银行家算法做死锁避免 |
| 工程化 | 把磁盘镜像格式写成规范文档、加版本号、做向前兼容 |
